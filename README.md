# LLM-Powered Log Triage for Incident Response

An LLM-powered incident-response assistant that analyzes system logs, groups related errors, identifies potential root causes, ranks them using supporting evidence, and generates a chronological timeline of an incident.

## Overview

Modern software systems generate large volumes of logs from applications, APIs, databases, servers, containers, and other infrastructure components. During an incident, engineers often need to manually inspect these logs to determine what happened, which errors are related, and what may have caused the failure.

This project aims to automate the initial log-triage process using a combination of conventional log processing and Large Language Model (LLM)-based analysis.

The system processes incident logs, extracts meaningful events, groups semantically related errors, analyzes their temporal relationships, generates potential root-cause hypotheses, ranks those hypotheses using available evidence, and produces a chronological incident timeline.

> **Important:** Root-cause results generated by the system are hypotheses based on available log evidence and should be verified by an engineer before being treated as confirmed causes.

## Project Objectives

1. To develop an LLM-powered log analysis pipeline that preprocesses incident logs, extracts meaningful events, groups semantically related errors, and correlates them using temporal and contextual information.

2. To identify and rank potential root causes using evidence from incident logs and automatically generate a chronological incident timeline that assists engineers in faster and more structured incident triage.

---

## Proposed Architecture

### 1. Log Input

The system accepts logs generated by supported applications, services, servers, or infrastructure components.

### 2. Preprocessing

Raw logs are normalized and relevant information such as timestamps, severity levels, services, error messages, exceptions, and metadata is extracted.

### 3. Event Extraction

Log messages are converted into structured events that can be analyzed by subsequent components.

### 4. Semantic Error Grouping

Related error messages are grouped according to their semantic similarity.

For example:

```text
Database connection refused
Database connection timeout
Unable to establish database connection
```

may be grouped as:

```text
DATABASE CONNECTIVITY FAILURE
```

### 5. Temporal Correlation

Events are ordered and analyzed according to their timestamps to identify the progression of the incident.

### 6. LLM Analysis

The structured incident context is provided to an LLM to generate potential root-cause hypotheses and supporting explanations.

### 7. Root-Cause Ranking

Potential causes are ranked using available evidence such as:

* Temporal precedence
* Error frequency
* Severity
* Semantic relationships
* Affected components
* Supporting evidence
* Contradicting evidence

### 8. Timeline Generation

The system generates a chronological representation of significant incident events.

### 9. Dashboard

The final results are presented through an incident-triage interface containing:

* Incident summary
* Error groups
* Root-cause candidates
* Supporting evidence
* Incident timeline

## Example

Input:

```text
14:02:10 ERROR Database latency increased
14:02:18 ERROR Database connection timeout
14:02:21 ERROR API request failed
14:02:25 ERROR User service unavailable
```

Possible output:

```text
Root-Cause Candidate:
Database connectivity failure

Supporting Evidence:
- Database latency increased first
- Database connection timeout occurred before API failures
- API and user-service failures occurred subsequently

Incident Timeline:
14:02:10 → Database latency increase
14:02:18 → Database connection timeout
14:02:21 → API failures
14:02:25 → User service failures
```

The output represents a **root-cause hypothesis**, not an automatically confirmed diagnosis.

## Installation

Clone the repository:

```bash
git clone https://github.com/<your-username>/<repository-name>.git
cd <repository-name>
```

Create a virtual environment:

```bash
python -m venv .venv
```

Activate it on Windows:

```bash
.venv\Scripts\activate
```

Activate it on Linux/macOS:

```bash
source .venv/bin/activate
```

```bash
pip install -r requirements.txt
```
